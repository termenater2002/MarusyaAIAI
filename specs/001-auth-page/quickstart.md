# Quickstart: Страница авторизации пользователей

## 1. Создай маршрут `app/(auth)/login/page.tsx`
- Используй серверный компонент для layout и клиентский компонент формы.
- Подключи общий layout `/app/(auth)/layout.tsx`, если требуется кастомное оформление.

## 2. Реализуй компонент `LoginForm`
- Поля: email, password; управляемая форма через React Hook Form или useState.
- Клиентская валидация email (regexp) и непустого пароля.
- Состояния `idle → submitting → success/error` по описанию в data-model.

## 3. Подключи API
- Отправляй `POST /api/auth/login` (см. contracts/auth.yaml).
- При `200` перенаправляй на `redirectTo` или `/dashboard`.
- При `401/423` выводи сообщение об ошибке из ответа или fallback.

## 4. Добавь ссылку на восстановление и регистрацию
- "Создать аккаунт" → `/register` (или другой роут, согласованный с продуктом).
- "Забыли пароль?" → модуль восстановления `/forgot-password`.
- Сделай их доступными с клавиатуры и screen reader (`aria-label`).

## 5. Состояние отправки и ошибки
- Дизейбли кнопки «Войти» при `submitting`, показывай спиннер.
- Используй `aria-live="polite"` для блока ошибок и подтверждений.
- Обнуляй поле пароля только после неудачной попытки.

## 6. Обнови навигацию
- В `site-config.ts` добавь пункт меню/кнопку, ведущую на `/login`.
- Убедись, что redirect из защищённых страниц ведёт на `/login`.

## 7. Покрытие тестами
- Напиши компонентные тесты на валидацию формы (React Testing Library).
- Интеграционные тесты на happy path и ошибочные сценарии (Playwright/Vitest e2e).

## 8. Чеклист перед PR
- Доступность: таб-навигация, контраст, корректные подписи.
- Мобильная адаптивность (ширина ≥ 320px).
- Все acceptance-сценарии из спецификации выполняются вручную.
