# Quickstart: Страница авторизации пользователей

## 1. Маршрут `app/(auth)/login/page.tsx`
- Серверный компонент страницы, клиентская форма в `login-form.tsx`.
- Используется layout `app/(auth)/layout.tsx` для центрирования контейнера.

## 2. Компонент `LoginForm`
- Поля: email, password; валидация email (regexp) и непустого пароля.
- Состояния `idle → submitting → success/error`; блокировка кнопки при submit.
- Сообщения об ошибках через `aria-live`; очистка пароля при ошибке.

## 3. Подключи API
- Отправляй `POST /api/auth/login` (см. contracts/auth.yaml).
- При `200` перенаправляй на `redirectTo` или `/dashboard`.
- При `401/423` выводи сообщение об ошибке из ответа или fallback.

## 4. Ссылки на восстановление и регистрацию
- "Создать аккаунт" → `/register`.
- "Забыли пароль?" → `/forgot-password`.
- Доступность: ссылки фокусируемые, hover/underline.

## 5. Состояние отправки и ошибки
- Дизейбли кнопки «Войти» при `submitting`, показывай спиннер.
- Используй `aria-live="polite"` для блока ошибок и подтверждений.
- Обнуляй поле пароля только после неудачной попытки.

## 6. Маршрут восстановления `app/(auth)/forgot-password/page.tsx`
- Форма ввода email, вызов `POST /api/auth/recover`.
- Показывай подтверждение нейтральным текстом, даже если аккаунт не найден.
- Ссылки назад на `/login` и `/register`.

## 7. Обновления навигации
- В `site-config.ts` есть пункты `/login` и `/register` для хедера.

## 8. Покрытие тестами
- Напиши компонентные тесты на валидацию формы (React Testing Library).
- Интеграционные тесты на happy path и ошибочные сценарии (Playwright/Vitest e2e).

## 9. Чеклист перед PR
- Доступность: таб-навигация, контраст, корректные подписи.
- Мобильная адаптивность (ширина ≥ 320px).
- Все acceptance-сценарии из спецификации выполняются вручную.
