# Research: Интерактивный навигационный бар

## Unknowns / NEEDS CLARIFICATION
- Как назвать CTA и страницу навигации (например, «Навигация» или «Гайды»)?
- Какие секции критичны на странице (минимум: гайды, обновления, обратная связь)?

## Best Practices
- Использовать семантический тег <nav> для доступности
- Для SPA-архитектуры — использовать Link/Router компоненты (например, next/link)
- Для адаптивности — скрывать пункты меню за бургер-иконкой на малых экранах
- Визуальная обратная связь: hover, active, focus состояния, анимации
- Проверять доступность (a11y): tab-навигация, aria-labels

## Alternatives Considered
- Классическое горизонтальное меню vs. вертикальное drawer-меню
- Реализация через кастомные компоненты vs. готовые UI-библиотеки (shadcn/ui, radix, material)
- Sticky vs. обычная навигация

## Decision
- Добавить одну CTA в хедер, ведущую на внутреннюю страницу `/navigation`.
- Страница статична, с секциями «Гайды», «Обновления», «Обратная связь».
- SPA-навигация через next/link, без доп. меню/бургера.

## Rationale
- Гибкость кастомных компонентов
- Соответствие UI-гайдлайнам проекта
- Лёгкая интеграция с существующей архитектурой Next.js
